Why Evaluate Agent Responses?

No Feedback Loop

Agents produce results but quality is unchecked — no systematic way to know if responses are correct or complete.

Silent Failures

Wrong data returned without detection — incorrect routing, missing results, or partial answers go unnoticed.

Manual Review

Human review by domain experts does not scale to the volume and variety of queries in a production system.

LLM-as-Judge vs. Programmatic

LLM-as-Judge

Structured Prompts

  • Multi-criteria scoring — correctness, completeness, routing
  • Flexible assessment — handles nuanced, open-ended judgments
  • Structured output — returns typed Score enums (PASS/PARTIAL/FAIL)
  • Trade-off — slower, costs per LLM call
Programmatic

Rule-Based Checks

  • Deterministic signals — API status, row counts, bundle presence
  • Fast execution — no LLM round-trip required
  • Binary outcomes — pass/fail on concrete conditions
  • Trade-off — rigid, cannot assess semantic quality
NextSeekEval uses: Hybrid — Programmatic signals feed into the LLM judge as structured context, combining speed with flexibility.

System Architecture

Two-Function Evaluator Design

JudgeAssistantResponse
function JudgeAssistantResponse( input: EvaluatorInput ) -> EvaluationJudgment enum Score { PASS PARTIAL FAIL } class EvaluationJudgment { correctness Score completeness Score routing_quality Score reasoning string }
DecideRetry
function DecideRetry( input: EvaluatorInput, judgment: EvaluationJudgment ) -> RetryDecision enum Verdict { PASS RETRY FAIL } class RetryDecision { verdict Verdict should_retry bool suggestions Suggestion[] retry_query string? }

Key Takeaways

  • Evaluators close the feedback loop — agents improve through structured assessment, not blind operation.
  • LLM-as-Judge provides flexible, multi-criteria quality scoring — correctness, completeness, and routing quality in a single pass.
  • Discriminated signals prevent one-size-fits-all evaluation — each path mode gets signals relevant to its execution.
  • Structured suggestions guide retry queries — not just "try again" but specific improvements with SuggestionCategory enums.
  • Type safety at every boundary prevents silent data corruption — Pydantic models, BAML types, and enum constraints throughout.
