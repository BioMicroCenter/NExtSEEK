# HARD CORRECTNESS RULES (read carefully)

## Field matching — exact vs. substring

When the user asks for samples WHERE A FIELD EQUALS A VALUE (e.g. "from the SHA lab",
"male mice", "in 2023", "treated with NDMA"), you MUST do an **exact comparison on the
identified field** — never a substring match across the whole row JSON.

WRONG (will produce hallucinated matches because UID strings often contain HTML wrappers
like `<a href="/seek/sample/id=12345/" target="_blank">D.SEQ-...</a>` whose URLs can
accidentally contain the search term):

    if "SHA" in str(row): ...       # BAD — matches URL fragments
    if "male" in row.get("uid", ""): # BAD — matches "female" via substring too

RIGHT:

    md = row.get("json_metadata") or {}
    if isinstance(md, str):
        try: md = json.loads(md)
        except Exception: md = {}
    if (md.get("Lab") or "").strip().upper() == "SHA":
        ...

For "from the X lab" / "from lab X":
1. Look for an explicit `Lab` field in the row's `json_metadata`.
2. If not present, check whether `field_index` lists a `Lab` field or similar (e.g.,
   `LabSlug`, `Institution`).
3. If no such field exists in the data, DO NOT substring-match the UID prefix to guess.
   Return `{"answer": "no Lab field present in this result; cannot filter by lab",
   "fields_checked": [...]}` and stop.

For sex / status / treatment / cohort filters: same rule — find the named field exactly
in metadata, do `.strip().upper() == "<VALUE>".upper()`, otherwise report "field not present".

## HTML wrappers on UID / title / uuid

If the data still contains HTML-wrapped UIDs (e.g.,
`"<a href=\"...\">D.SEQ-...-PUB</a>"`), STRIP the tags before matching.

Use the **bound helper** `strip_html(s)` — it's always available in your
runtime, returns the tag-free trimmed string. This is the canonical path.

`try/except` IS allowed and is the right pattern for safely parsing
optional metadata (e.g., `json_metadata` may be a JSON string OR a dict):

    md = row.get("json_metadata") or {}
    if isinstance(md, str):
        try:
            md = json.loads(md)
        except Exception:
            md = {}

`while` loops, `import`, function/class defs, `with`, `raise`, `del`, and
`lambda` are all VALIDATOR-FORBIDDEN — your code silently falls back to
the slow legacy path. Stick to flat statements, conditionals, for-loops,
list/dict/set comprehensions, and try/except.

Example (CORRECT use of strip_html + try):

    val = strip_html(row.get("uid", ""))
    md = row.get("json_metadata") or {}
    if isinstance(md, str):
        try:
            md = json.loads(md)
        except Exception:
            md = {}
    if (md.get("Lab") or "").strip().upper() == "SHA":
        matched.append(val)

## When the requested filter cannot be computed

ALWAYS prefer "I don't have that field" over guessing. Examples of correct
`result` payloads in that case:

    {"answer": "no `Sex` field found on any row; cannot filter by sex",
     "fields_checked": ["json_metadata.Sex", "Sex"],
     "total_rows": 195}

    {"answer": "no `Lab` field present in this result set",
     "fields_checked": ["json_metadata.Lab"],
     "total_rows": 264,
     "note": "the original search used 'SHA OR lab' as a free-text keyword; results may not be lab-scoped"}

## Quality-of-evidence on filters

When you DO match a filter, include in your `result`:
- `count`: how many rows matched
- `examples`: up to 5 example UIDs
- `field_used`: the exact field path you compared on
- `match_strategy`: "exact" / "case-insensitive exact" / "substring"

Use "substring" only when the user explicitly asks for it (e.g., "containing the word X").
