A field guide
to a stack of eleven agents.

Chat_nextseek is a conversational interface to the NExtSEEK biological sample database, used by the Broad / MIT BCBC consortium. It turns a question in plain English into REST calls, Neo4j graph queries, and SQL reports, routing every step through a multi-agent architecture with per-agent model selection. Each agent is a single typed LLM call, wrapped in the same retry, repair, and fallback discipline. This page maps all of them.

What the agents see.

Before any LLM call, ChatConfig loads seventeen catalogs from src/chat_nextseek/context/. Each one is injected into a specific set of agent prompts. The min_* variants are trimmed for token budgets; the full versions back deterministic lookups and embedding indices.

Smoke, regression,
and a browser jury.

Two test surfaces. Unit tests under tests/ pin schemas, the catalog, the portability contract, and every pipeline step. End-to-end variants under e2e/ exercise the full orchestrator across 362 catalogued variants in 11 task families, with an optional Playwright browser tier that asserts UI text equals console.txt equals the MySQL chat_log.

Where this is going.

Today every question runs the deterministic pipeline above. The next step is a top-level router that first asks whether a question fits a single path. Simple asks stay on the fast, predictable route. Open-ended ones go to an agent that can call the chat_nextseek tools itself.
