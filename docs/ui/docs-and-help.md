# Docs and help surfaces

## What this covers

Every place the site tells a user how to use it, as the tree stands today: the in-app Getting
Started page, the API docs pages (Swagger, ReDoc, schema), every link to the external GitBook
documentation, the contact address, and the fact that Nessie's own knowledge of the docs is built
from that GitBook site. It also records what does not exist (an About page, footer links).

It does not cover the sidebar and footer markup in general (see [shell.md](shell.md)), other pages
([pages.md](pages.md)), or the chat UI ([chat-frontend.md](chat-frontend.md)). The user docs are
moving into the repo; see "Planned" at the end.

## How it works

There is one in-app help page. It is a static template with no data: a view renders it and nothing
else. Everything longer than that lives on an external GitBook site, which the live UI links to from
two templates. Nessie (the assistant) answers documentation questions from a snapshot of that same
GitBook site, generated by a build tool and committed under `NessieAI/`.

```
GitBook site (external) --> 2 live links in templates (sidebar, help page)
        |
        +--> NessieAI/build_tools/ingest_nextseek_docs --> NessieAI/docker/cc-runtime/docs/nextseek/*.md
                                                            (what Nessie's Claude Code container reads)
```

So changing where the docs live changes two things: what users click, and what Nessie knows.

The team's support address is used as a `mailto:` in two places: the sidebar "Contact

## Where to edit

| Task | Files and steps |
|---|---|
| Change Getting Started text | `themes/NextSeek/templates/help/getting_started.html`. Keep strings inside `{% trans %}` or `{% blocktrans trimmed %}`. Text outside `{% block main %}` is dropped because the template extends `base.html` |
| Change the help route or view | `seek/urls.py` (`getting_started`), `seek/views/pages.py`; the view is re-exported through `seek/views/__init__.py` |
| Change the sidebar "Getting Started", "Documentation" or "Contact Support" entries | `themes/NextSeek/templates/nav.embed.html` (Resources section and `#usefulInfoSubmenu`) |
| Add a docs link to the home page | `themes/NextSeek/templates/index.html` (the home page has none today) |
| Add footer links | `themes/NextSeek/templates/page-footer.embed.html` |
| Change the Swagger look | `themes/NextSeek/templates/nextseek/swagger_ui.html`; route in `nextseek_api/urls.py` |
| Change which docs Nessie reads | `NessieAI/build_tools/ingest_nextseek_docs/constants.py` (`DEFAULT_DOC_URL`), `fetch.py`, then regenerate the snapshot under `NessieAI/docker/cc-runtime/docs/nextseek/`. Update the pinned tests in `NessieAI/tests/build_tools/` in the same change |
| Add any new public page | Declare a `Route` in `ci/routes.py` (model it on the `/seek/help/` entry); the blocking gate `ci/gate/test_route_registry.py` fails until you do. Mount it in `dmac/urls.py` before the Mezzanine catch-all |

## Gotchas

- Theme templates are found by name, so the file must stay at
  `themes/NextSeek/templates/help/getting_started.html` (see `themes/README.md`).
- nginx caches `/static/` for 30 days. `nextseek.css` gets a content-hashed name, but anything
  referenced by a plain path can stay stale in a browser; hard-reload before blaming a deploy.
- Moving docs off GitBook silently changes Nessie: its snapshot is only as current as the last run
  of the ingester, and the ingester only understands GitBook's output.
- Mezzanine's catch-all in `dmac/urls.py` swallows any route mounted after it. Mount new pages
  before it.
- `docs/ui/` is for developers. It is not a user-docs location and `ci/docs_map.py` polices markdown
  under tracked live-doc folders (relative links must resolve, no email addresses).

## Content drift (today's help text versus the UI)

| Help text says | The UI now |
|---|---|
| Type into the "Ask Nessie..." input in the sidebar | The sidebar has an "Ask Nessie" button (`themes/NextSeek/templates/includes/nessie_button.html`, links to `/seek/assistant/`). The text input under "Quick Access" (`#search-uid`) is a UID search |
| Open the chat via the "Talk to Nessie" link on the home dashboard | The home page (`index.html`) has an "Ask Nessie" button (the same `includes/nessie_button.html`) in its actions column. |
| Uploading, searching, workflows | Written before graph (Neo4j) search; neither the help page nor the GitBook text mentions it |

The GitBook upload templates are dated 2024; the site now generates templates at `/seek/templates/`.

## Known issues

See [known-issues.md](known-issues.md#docs-and-help). The ones that matter most here:

- The help text names UI elements ("Ask Nessie..." sidebar input, "Talk to Nessie" link) that no
  longer match the sidebar or home page.
- Two docs entries (sidebar "Getting Started" and "Documentation") point at different places with no
  explanation, and the footer has no About, Contact or Docs links.
- Nessie's docs knowledge depends on a third-party site-index format, and the Swagger, ReDoc and
  schema pages answer logged-out visitors with an API auth error instead of a login redirect.
