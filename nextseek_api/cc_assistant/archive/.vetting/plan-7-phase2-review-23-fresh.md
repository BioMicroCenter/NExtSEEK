## 2B — Stress test

**[MEDIUM] The `shared` mount is in the spawn set but absent from the Subpath-VALUE isolation enumeration, and the negative-control rule contradicts its legitimate value.** Current `_build_volumes` (cc_engine.py:363–395) mounts **six** trees, including `dirs.shared_src → /data/shared` (RO). `shared_src` is **project-scoped**: `cc_provision.py:101` `shared_src=f"{project_host}/shared"` → subpath tail `proj/shared` (no user segment, by SPEC-2 D5 design — shared is shared across users within a project). Task 6 Step 4 keeps `/data/shared` in the sibling mount list, but Task 6 Step 1 "Per-user Subpath VALUE isolation" enumerates only **input/scratch/cc-state/transcripts** and states the negative control as: *"a mount whose `Subpath` … **omits the per-user `{project_dirname}/{user_id}/` prefix** MUST fail the test."* Applied literally to `/data/shared` (`proj/shared`), that rule **falsely fails the correct shared mount**; applied only to the four enumerated mounts, `shared`'s Subpath is left **hermetically unguarded** (a one-line `shared` `Subpath=""` mutation passes the hermetic suite). Why a defect: the centerpiece OI-3 anti-leak test is internally contradictory and silent on a mount that is actually spawned. *Backstop that caps severity at MEDIUM:* the live gate's `find` roots include `/data/shared` (Task 10 Step 4), so a `Subpath=""` shared leak still surfaces the seeded `otherproj/bob` token in-turn ⇒ RED — the leak cannot ship green overall. **Fix:** in Task 6 Step 1, (a) add `shared` to the enumeration with its correct project-scoped expected value (`proj/shared`), and (b) reword the negative control to require the correct *expected per-mount* Subpath (exact-string equality per mount) rather than a blanket "must contain `{project}/{user}/`" rule that misclassifies the project-scoped `shared` mount.

**[MEDIUM] The "strip `user_root_mount` from the `*_mnt` path `build_user_dirs` produces" derivation rule does not map cleanly onto the real (or refactored) field set, for input and transcripts.** Task 6 Step 1/Step 2 state the Subpath "equals the per-user `*_mnt` path that `build_user_dirs` produces with the `user_root_mount` prefix stripped." But in the current `UserDirs` (cc_provision.py:60–76) there is **no `input_mnt`** (only `input_src`, a host path) and **no `transcripts_mnt`** — `memory_mnt` is `…/_memory/sess` while the required transcripts Subpath is `proj/alice/_memory/sess/**transcripts**` (a child dir, not a bare `*_mnt`). The plan separately says UserDirs gains `*_subpath` fields and `build_user_dirs` is refactored, so the rule describes a future shape — but the same task mixes three vocabularies (`*_mnt`, `*_subpath`, "strip prefix") and the general rule is wrong for input (no `*_mnt`) and transcripts (`memory_mnt` + `/transcripts`). Why a defect: a cold implementer reconciling "strip prefix from `*_mnt`" against the concrete enumerated values can derive `proj/alice/_memory/sess` (no `/transcripts`) for transcripts, or be unsure where the input subpath comes from. The concrete enumerated values are authoritative and resolve it, so this is a clarity/stall risk, not a leak. **Fix:** state the derivation as "each sibling Subpath equals its **explicit enumerated value** below" and drop/repair the lossy "= `*_mnt` stripped" generalization; specify that transcripts = `memory` tail + `/transcripts` and that input/shared acquire their subpath via the new `*_subpath` fields.

**[LOW] Subpath-target precondition (dir must pre-exist in the volume) is covered but easy to under-implement.** Engine `VolumeOptions.Subpath` fails container start if the subdir is absent in the volume. Task 6 Step 4 point 6 ("spawn only after provision mkdir for every subpath … hermetic negative test: mount/spawn fails when subpath dir missing") covers this, including the `.claude` and the transcripts child dir via "every subpath." No defect — noting it because it is the most likely *runtime* failure if "every subpath" is read narrowly (the `_memory/<session>/transcripts` child specifically must be mkdir'd, not just `_memory/<session>`).
